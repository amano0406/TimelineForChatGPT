# E2E Smoke

`chatgpt2timeline` now includes a pragmatic smoke-style E2E runner that exercises the current scaffold end to end:

1. build the web app
2. start the local ASP.NET Core server
3. open `/jobs/new`
4. submit a real multipart ZIP upload through the actual Razor Pages form
5. run the Python worker once
6. verify a successful run and a corrupted ZIP failure
7. verify English and Japanese UI labels on `/jobs`, `/jobs/{id}`, and `/jobs/{id}/conversations/{conversationId}`

## Entry Points

PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\apps\chatgpt2timeline\tools\e2e\run-smoke.ps1
```

Bash / WSL:

```bash
/mnt/c/apps/chatgpt2timeline/tools/e2e/run-smoke.sh
```

## Fixture Strategy

The runner builds two temporary ZIP files under `C:\Codex\workspaces\chatgpt2timeline-e2e\fixtures`:

- `sample-good-export.zip`
  - generated from `C:\Codex\workspaces\chatgpt2timeline-smoke\export` by default
  - you can override the source with `-FixtureSourceRoot`
  - currently packages:
    - `export_manifest.json`
    - `conversations-000.json`
    - `analysis_summary.json` when present
- `sample-bad-export.zip`
  - generated by truncating the good ZIP so it loses the ZIP central directory

That keeps the smoke test small enough to re-run quickly while still using a real ChatGPT export structure.

## Output

The runner writes reusable artifacts under `C:\Codex\workspaces\chatgpt2timeline-e2e`:

- `runtime/`
  - isolated app-data, uploads, outputs, and web logs
- `artifacts/`
  - captured HTML and HTTP headers
- `report.json`
  - final summary with generated job ids and run directories

## Current Scope

This smoke runner does not use a browser automation framework yet. It is intentionally lighter:

- it uses the real HTTP form POST path, including anti-forgery token handling
- it uses the real worker
- it asserts localized UI text and generated output files

If the product grows, the next step is a fuller browser-driven suite for `upload -> poll -> inspect -> download`.
