# AGENTS.md

## Repo purpose

This repository is `TimelineForChatGPT`.
Its job is to turn local ChatGPT export data into timeline-oriented artifacts that stay readable, structured, and easy to hand to another LLM.

## Must preserve

- Keep the product local-first.
- Treat CLI / worker / output artifacts as the source of truth.
- Do not add a web UI unless the product requirement explicitly changes again.
- Do not delete, overwrite, mass-move, or mass-rename original export inputs.
- Preserve conversation order, message order, and attachment references.
- Keep gaps, warnings, missing attachment handling, and fidelity limits visible.
- Prefer fixed input/output/state roots by default rather than arbitrary one-off path workflows.

## Product-specific guardrails

- Preserve `request.json`, `status.json`, `result.json`, `manifest.json`, timeline markdown, and index outputs.
- Keep attachment inventory explicit even when the binary or derived text is not fully processed.
- Do not hide branch/path ambiguity. If normalization is best-effort, say so in artifacts or docs.
- Keep Docker / `docker compose` style entrypoints reproducible when they exist.

## Standard model

```text
InputSource = configured input source
InputItem   = detected processable input from InputSource
Job         = processing request based on an InputItem snapshot and profile
Run         = one execution attempt for a Job
Artifact    = output generated by a Run
```

## Safe work without extra confirmation

- read-only investigation
- `AGENTS.md`, README, docs, and `.env.example` updates
- non-destructive small code fixes
- lightweight unit or smoke checks
- Docker build / compose smoke checks
- output contract consistency fixes that do not remove user data

## Ask before doing these

- deleting or rewriting raw export inputs
- mass move / mass rename of user files
- breaking output contract changes
- repo or product rename
- new hosted/cloud dependency
- deploy, external posting, or secret changes
- broad architecture rewrites

## Before finishing

- Read the README and contract docs first.
- Keep current output shape stable unless the task explicitly changes it.
- Update docs when behavior or contracts change.
